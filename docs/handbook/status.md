# Published and source features

The published baseline is CLI **0.1.19**, runtime **0.1.9**, and macros **0.1.7**.
The checked-out manifests still use those versions, but the working tree includes
new, **unpublished** APIs. A version number in a local manifest does not mean
these changes are already on crates.io.

## Availability

| Capability | Current generator default | Local runtime setup |
| --- | --- | --- |
| MVC resources | Controller → service → repository | Generated by default |
| CQRS resources | Controller → handler → repository | `--cqrs`; saved architecture |
| Create DTO | Generated under `dto/mod.rs` | `Deserialize`, `Validate`, `JsonSchema` |
| Search/path/form DTOs | Examples in comments | Add DTO types and handlers explicitly |
| Module imports | An imports section and usage guide | Export dependencies and register every module definition |
| Async providers/hooks | Sync startup helpers remain generated | Await `initialize_async`; explicit cleanup hooks |
| PostgreSQL | In-memory repository remains generated | `postgres`, pool/migration provider, repository SQL |
| JWT/permissions | Generated resources remain public | `auth`, verifier and guards |
| Background jobs | No queue is created | `jobs`, bounded queue provider and shutdown |
| Memory/Redis cache | No automatic caching | `cache` or `cache-redis`, explicit keys/TTLs |
| CQRS buses/events | Direct handler calls remain generated | `cqrs`, typed registrations and controller changes |

CLI templates currently specify a crates.io runtime dependency at version 0.1.8.
Cargo's compatible 0.1 patch range may resolve newer published releases, but it
cannot resolve unpublished local changes. Use `--runtime-path` or an explicit
local dependency to try the new features.

## Updating a CLI does not migrate an app

```sh
cargo install xecute-cli --version 0.1.19 --locked --force
```

This updates the CLI executable. It does not rewrite existing application source,
change generated Cargo features, replace repositories, protect routes, or migrate
application startup to async lifecycle.

For source development from the repository root:

```sh
cargo install --path xecute-cli --locked --force
xecute new local-api --runtime-path "$PWD/xecute"
```

The path must point at the nested `xecute` crate, not the workspace root. In an
existing app, merge the corresponding local path and feature flags into its
manifest. Workspace apps inherit their dependency through `[workspace.dependencies]`.
See [adopting an existing app](/docs/getting-started/adopting-existing).
