# Build your first API

By the end of this guide, you will have a running Rust API, create a record, and
see it in a response. Start with MVC; you can learn CQRS after your first feature.

## 1. Check your tools

You need Rust **1.98.1 or newer**, Cargo, rustfmt, and Clippy. Generated projects
pin Rust 1.98.1 in `rust-toolchain.toml`.

```sh
rustc --version
cargo --version
rustup component add rustfmt clippy
```

No database, Redis, or authentication provider is needed for this tutorial.
The generated repository stores records in memory.

## 2. Install Xecute

Run this from any directory:

```sh
cargo install xecute-cli --version 0.1.19 --locked
xecute --version
```

The version command should print `xecute 0.1.19`. If the command is missing, check
that Cargo’s `bin` directory is on your `PATH`. To replace an existing CLI install,
add `--force` to the install command.

## 3. Create a project

Run this from the directory where you keep your projects:

```sh
xecute new my-api
cd my-api
```

This creates an MVC application and an `example` feature. MVC means your HTTP
controller calls a service, and the service calls a repository. You do not need
to wire the generated example yourself.

The generator resolves a fresh `Cargo.lock` using the latest
compatible dependencies. Keep that file in Git. A network failure leaves the
project files available; enter the project and retry `cargo generate-lockfile`.
Breaking dependency versions are not automatically adopted.

## 4. Start the server

Keep this terminal open:

```sh
xecute run dev
```

The first build can take longer because Cargo downloads and compiles dependencies.
The default server address is `http://127.0.0.1:3000`. The development runner
watches source files and rebuilds when you save a change. Use `cargo run` if you
prefer a single run without watching.

Open `http://127.0.0.1:3000/docs/` for your application’s Swagger UI. This is the
API documentation generated by your app, separate from this Xecute learning site.

## 5. Send your first requests

Open a **second terminal**. Keep the server running in the first one.

```sh
curl -i http://127.0.0.1:3000/example
```

Expect `200 OK` and an empty collection. Now create a record:

```sh
curl -i -X POST http://127.0.0.1:3000/example \
  -H 'Content-Type: application/json' \
  -d '{"name":"My first record"}'
```

Expect `201 Created` and a record containing a generated UUID and your name.
Run the GET request again to see the saved record. The generated middleware may
wrap response data; use Swagger to inspect the response contract.

Records disappear when the server restarts. You have not connected a database yet.

## 6. Try an invalid request

```sh
curl -i -X POST http://127.0.0.1:3000/example \
  -H 'Content-Type: application/json' \
  -d '{"name":"A"}'
```

Expect `422 Unprocessable Entity`. Names must contain 3–100 characters and cannot
be whitespace only. Xecute checks the DTO before calling the controller method;
you do not add a manual validation call to the handler.

## If something does not work

| What you see | What to do |
| --- | --- |
| `xecute: command not found` | Check Cargo’s bin directory in `PATH`, then reopen the terminal |
| Downloads or dependency resolution fail | Check registry/network access; run `cargo generate-lockfile` in the generated app |
| Port 3000 is already in use | Stop the other server or change the listener configuration in `config/AppConfig.toml` |
| POST returns `415` | Add `Content-Type: application/json` |
| POST returns `422` | Use the `name` field with 3–100 nonblank characters; remove unknown fields |
| GET is empty after saving code | The watcher restarted the app, clearing the in-memory repository |
